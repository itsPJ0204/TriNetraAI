# Semantic AI Integration Contract & Interface Specification

## 1. Overview & Responsibility Boundaries

This document defines the interface boundary between **Role 1 (Data Engineering / Ingestion & Tiling)** and **Role 2 (Semantic AI)** in the satellite semantic search architecture.

### Architectural Separation of Concerns

```
+-------------------------------------------------------------+
|               ROLE 1: DATA ENGINEERING                     |
|  - GeoTIFF ingestion & validation                           |
|  - Cloud-optimized / multi-tile raster grid splitting       |
|  - CRS & geospatial coordinate extraction                   |
+-------------------------------------------------------------+
                              |
                              | [Tile files & GeoTIFF Metadata]
                              v
+-------------------------------------------------------------+
|                   ROLE 2: SEMANTIC AI                       |
|  - RemoteCLIP image preprocessing & 512-D embedding         |
|  - Vector index upsert (Qdrant `satellite_tiles`)          |
|  - Natural-language query normalization & text embedding   |
|  - Vector similarity search & 2D bbox filtering             |
|  - Output `SearchResult` domain objects                     |
+-------------------------------------------------------------+
                              |
                              | [Clean Domain Models: SearchResult]
                              v
+-------------------------------------------------------------+
|                 ROLE 3 / DOWNSTREAM SERVICES                |
|  - FastAPI REST Endpoints                                   |
|  - Web UI / Map Client                                      |
+-------------------------------------------------------------+
```

### Key Principles

1. **Ingestion Ownership**: Semantic AI does **not** own raw satellite imagery downloading, sensor calibration, or large-scale raster tiling pipelines. Role 1 produces standardized GeoTIFF tiles.
2. **Standardized Input Contract**: Semantic AI consumes tile images and their metadata schema to generate vector embeddings and index them in Qdrant.
3. **Dataset Scalability**: The initial 4 tiles (`tile_1.tif` to `tile_4.tif`) represent the development and baseline benchmark dataset. The Semantic AI module is architected to scale to arbitrary tile and scene counts.
4. **Decoupled Downstream Consumption**: Downstream API and frontend layers interact solely through `semantic_search.search()` and `SearchResult` without direct dependency on Qdrant or RemoteCLIP internals.

## 2. Role 1 -> Role 2 Data Contract

For each satellite image tile generated by the ingestion pipeline, Role 1 delivers a valid GeoTIFF file accompanied by the following metadata fields:

| Field Name | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `image_path` | `str` | Absolute or workspace-relative path to GeoTIFF file | `"data/tiles/tile_1.tif"` |
| `tile_name` | `str` | Unique tile identifier filename | `"tile_1.tif"` |
| `crs` | `str` | Coordinate Reference System identifier (prefer EPSG:4326) | `"EPSG:4326"` |
| `bounds` | `dict` | Geospatial extent dictionary with keys: `left`, `bottom`, `right`, `top` | `{"left": 88.34, "bottom": 22.57, "right": 88.36, "top": 22.58}` |
| `width` | `int` | Pixel width of the tile | `233` |
| `height` | `int` | Pixel height of the tile | `191` |
| `date` | `str` | Acquisition date (ISO 8601: `YYYY-MM-DD`) | `"2025-03-29"` |

### Tile Format Constraints
- **File Format**: Standard GeoTIFF (`.tif`, `.tiff`).
- **Color Bands**: 3-channel RGB or multi-band imagery where first 3 channels represent visible spectrum (normalized to `uint8` [0-255] during preprocessing).
- **Coordinate System**: Bounding box coordinates must be strictly valid (`left < right` and `bottom < top`).

---

## 3. Semantic AI Processing Pipeline

When tiles are submitted to the Semantic AI indexing workflow:

```
Role 1 GeoTIFF Tile
        ↓
Rasterio metadata extraction (CRS, bounds, dimensions)
        ↓
RemoteCLIP image preprocessing (224x224 RGB tensor normalization)
        ↓
RemoteCLIP ViT-B/32 vision encoder
        ↓
L2 normalization → 512-dimensional float32 vector
        ↓
Qdrant `satellite_tiles` collection upsert (Vector + Payload Metadata)
```

## 4. Role 3 (FastAPI & Application Layer) Integration Guide

Role 3 (FastAPI backend / web client) can directly import and invoke the semantic search engine.

### 4.1 Quickstart Import & Execution

```python
from semantic_search import search, SearchResult

# Query the index with natural language
results: list[SearchResult] = search("buildings near a river", top_k=5)

for res in results:
    print(f"Tile: {res.tile_name} (Score: {res.score:.4f})")
    print(f"  Path: {res.image_path}")
    print(f"  CRS: {res.crs}")
    print(f"  Bounds: {res.bounds}")
    print(f"  Dimensions: {res.width}x{res.height}")
    print(f"  Date: {res.date}")
```

### 4.2 SearchResult Schema & Metadata Attributes

Every result returned by `search()` is an instance of `SearchResult` containing 8 typed metadata attributes:

| Attribute | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `tile_name` | `str` | Tile filename identifier | `"tile_1.tif"` |
| `image_path` | `str` | Relative path to the tile GeoTIFF | `"data/tiles/tile_1.tif"` |
| `score` | `float` | Cosine similarity score | `0.2814` |
| `crs` | `str` | Coordinate reference system | `"EPSG:4326"` |
| `bounds` | `dict[str, float]` | Bounding box (`left`, `bottom`, `right`, `top`) | `{"left": 88.34, "bottom": 22.57, "right": 88.36, "top": 22.58}` |
| `width` | `int` | Raster pixel width | `233` |
| `height` | `int` | Raster pixel height | `191` |
| `date` | `str` | Acquisition date (ISO 8601: `YYYY-MM-DD`) | `"2025-03-29"` |

### 4.3 Advanced Options: Geographic Bounding-Box Filtering

Role 3 can optionally constrain natural-language search within a spatial bounding box:

```python
from semantic_search import search

bbox = {
    "left": 88.345,
    "bottom": 22.572,
    "right": 88.360,
    "top": 22.585,
}

results = search("buildings near a river", bbox=bbox, top_k=5)
```

### 4.4 FastAPI Endpoint Example

Role 3 can expose semantic search in a FastAPI router seamlessly using `.to_dict()` or Pydantic:

```python
from fastapi import FastAPI, HTTPException, Query
from semantic_search import search

app = FastAPI(title="Satellite Semantic Search API")

@app.get("/api/search")
def search_tiles(
    q: str = Query(..., description="Natural language search query"),
    top_k: int = Query(5, ge=1, le=50, description="Max results"),
    min_lon: float | None = None,
    min_lat: float | None = None,
    max_lon: float | None = None,
    max_lat: float | None = None,
):
    try:
        bbox = None
        if None not in (min_lon, min_lat, max_lon, max_lat):
            bbox = {
                "left": min_lon,
                "bottom": min_lat,
                "right": max_lon,
                "top": max_lat,
            }
        results = search(query=q, bbox=bbox, top_k=top_k)
        return {"query": q, "count": len(results), "results": [r.to_dict() for r in results]}
    except ValueError as err:
        raise HTTPException(status_code=400, detail=str(err))
    except Exception as err:
        raise HTTPException(status_code=500, detail=f"Search service error: {err}")
```
